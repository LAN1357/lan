# 本地经营复盘工作台使用说明

新版浏览器入口分为`月份总览 → 结算工作台 → 经营分析`。结算工作台仍是四步：`数据导入 → 确认订单属于哪场 → 业务与费用确认 → 关账与导出`。左侧步骤栏持续显示进度，系统会自动进入当前应处理的步骤；每个操作区会说明“为什么要做、完成后去哪里”。业务计算、候选规则、确认、关账和分析仍由确定性逻辑执行，界面改版没有改变财务口径。浏览器不提供聊天；关账后可复制分析引用到Codex或Claude Code继续追问。

## 启动

在项目根目录执行：

```bash
cd /absolute/path/to/lan
python3 -m src.workbench.app
```

浏览器打开 http://127.0.0.1:8765 。裸首页是月份总览；`/workbench`是结算工作台，`/analysis`是只读经营分析。按 `Ctrl+C` 停止。默认使用独立 `data/workbench.db`，不存在时自动创建，不能指定旧 `roi_agent.db`。如端口被占用，使用 `--port 8766`。

新版仅需要 Python 3.11+ 和现有 `openpyxl`。尚未安装项目依赖时，可以先执行 `python3 -m pip install 'openpyxl>=3.1.0'`；测试另需 pytest。界面不需要 Node、云服务或额外前端框架。

为避免合成账例混入正式数据，首次演练可使用单独文件：

```bash
python3 -m src.workbench.app --db data/m2-trial.db
```

## 先看今天这场的经营利润

在页面顶部选“所选场次全部”，选中今天的场次并点击“切换范围”。继续切换订单、费用和步骤4，处理范围保持不变。步骤4显示该场完整收入、商品履约成本、最终佣金和投流分配；其他已明确归属场次缺成本，不再阻止这场预览。结果标注“局部结果，非全月利润”，月度费用仍不纳入。

“本次导入”用于限定日常待办；预览利润时，会依据批次记录及已确认归属确定涉及场次，读取这些场次历次导入的完整数据，而不是只计算本次新增几行。只补商品履约费用的批次也能找到对应订单。订单搜索与分页不会缩小利润计算范围；未明确关联任何场次的批次不会自动展示整月金额。

未归属订单、未分配投流仍会列出：已有明确来源范围且属于其他场次的记录不纳入局部结果；可能涉及当前场次或来源范围未知的记录，补核前不展示利润。不会仅凭支付时间不同就排除跨期业务。若当前场次没有已确认订单，也不会把缺收入当作零收入。

业务适用性、直接费用待办和投流列表跟随当前处理范围。月度共享费用、账号计划的整月关联配置、完整来源的跨场分配及正式关账会明确标注范围；共享投流仍须校验整笔来源金额守恒。完整关账核对按整月进行，返回日常步骤仍保留原处理范围。

## 按四步完成一次复盘

1. **数据导入**：先选择“新增直播场次”或“补充或更正已有场次”，再上传标准模板。新增模式生成内部场次编号并展示来源映射；补充模式选择已有场次，但该选择不会把文件订单自动改绑。预览分别列出新增、更新、未变和冲突，确认后才原子入账。
2. **确认订单属于哪场**：在“本次导入 / 所选场次全部 / 本月全部”之间切换。单场文件可直接选择场次并“预览并确认到本场”；多场文件才使用“按直播时间匹配”。候选只是建议，异常仍需人工判断。
3. **业务与费用确认**：先确认场次业务范围和投流关联，再处理投流与月度费用分配。商品成本使用按当前范围自动汇总的多SKU表，一次为不同SKU填写不同单价；只补空缺实际记录，不覆盖已有成本或猜测履约数量。月度权重复用只在存在有效参考方案和其他目标费用时出现。
4. **关账与导出**：未关账时默认预览不含月度费用的经营利润；月末切换“完整费用核对与关账”，处理完整关账阻断项、核对双利润并确认费用清单完整后关账，随后下载正式 Excel。重开须填写原因；再次关账生成 V2，V1 保留在历史中。

关账完成后点击“查看经营分析”。看板只读取该版关账副本：先看概览和重点场次，再按需展开场次证据、两类比较或条件测算。历史版入口明确标为`mode=history`；有新版时不会静默切换。

页面不会在每次提交后把人送回顶部：预览、确认、费用维护等操作会返回对应工作区。切换步骤、筛选订单、维护费用、分页和切换利润口径都会保留当前场次或导入批次。每一步顶部均可明确切换“本次导入 / 所选场次全部 / 本月全部”。切换业务月份会明确回到该月全部范围。

每次上传为一个来源批次；“整月关账批次”包含同一开播月份的所有场次，二者不是同一个概念。整月关账仍阻断尚未归属的已导入订单和投流，即使其支付月份不同，以免漏掉跨期业务；请先处理这些来源记录。

导入批次保存独立成员清单，不通过业务记录当前的`batch_id`倒推。因此，同一订单后续补充结算信息后，首次导入和补充批次仍都能定位该订单。本次范围默认只看新增和更新；“未变旧记录”单独切换查看，不计为本次新完成事项。空新增批次会提示“没有新增数据”。

## M2：减少逐条处理

### 订单候选与批量确认

1. 默认进入“全部待处理”。订单表优先展示订单号、子订单/行号、SKU、支付时间、候选场次和最终场次，每页50条。已归属订单按所选开播业务月份显示；尚未归属订单没有确定业务月份，需用支付日期或时间缩小范围。时间填到分钟时，截止时间包含该分钟。
2. 选择本页记录，或选择“处理全部筛选结果（跨页）”。展开“生成候选的场次范围”，核对场次并明确确认订单与直播的业务范围，再生成候选。
3. 固定规则仅检查支付时间是否落入所选场次的完整时间区间；支持跨午夜，区间左闭右开。没有覆盖、多个直播同时覆盖、恰在开播/结束边界，或未确认来源范围，均进入异常待判断。没有概率、评分、延迟支付推断，也不会据时间直接写入最终归属。
4. 筛选“有候选待确认”，选择记录并预览。可一次确认不同订单各自的明确候选。异常订单改用人工指定场次并写明依据；已有确认结果的更正须明确勾选允许更正。
5. 预览展示处理条数、结果分组、原值与拟采用结果，可下载全部明细。最终确认只处理本次预览确定的记录；预览后新增记录不被带入。来源、场次、人工决定或采用的关联依据改变时，整批拒绝，需重新预览。

每笔人工确认记录修改前后值、依据、时间和共同批量编号。重复点击确认不会重复写入；处理中出错则整批回滚。重跑规则追加候选历史，不改变原人工决定。通过每行“处理依据”查看全部候选及决定历史。预览保存在本次服务内，重启或连续创建超过10份预览后，旧预览可能失效，重新预览即可。

### 费用状态与实际费用批量维护

费用待办分开显示“数据情况”和“处理情况”：例如金额已取得但待分配、成本未取得、待确认订单归属、待补齐结算依据、适用范围冲突或需复核。默认只显示待处理费用，可切换全部费用。直接费用按当前处理范围展示，月度费用明确标为整月共享。

“未取得”、实际0元、“不适用”继续分别保存。字段明细中可逐项查看；队列状态是处理提示，是否可以关账仍由完整检查决定。赠品与损耗等存在业务冲突时，不会因为填写了“不适用”而绕过关账。

同类履约或达人记录中，已确认相同实际金额的字段可以批量填写，如运费险、物流费、赠品、损耗、最终佣金、坑位费或达人调整。先勾选记录和同一字段，预览后填写统一依据；默认不覆盖已有金额，需要更正时明确允许。达人最终结算依据仍由人工提供，不根据佣金率推算最终金额。

### 已确认方案复用

| 能力 | 操作与限制 |
|---|---|
| 批量业务范围 | 勾选本月场次，一次明确四项业务适用性，预览后确认；原状态与修改依据逐场保留 |
| SKU单位成本 | 当前处理范围自动汇总相关SKU；可一次选择多个SKU并分别填写单位成本，预览影响订单后统一确认。仅补齐已确认归属、已有履约记录且单位成本为空的订单；不覆盖已有单价，也不创建或猜测实际出库/退回数量。是否另存本月通用标准必须明确选择 |
| 投流关联 | 按原始账号、计划与业务月份精确关联已确认受益场次；每月单独维护范围。在投流表生成候选，只有小时区间完整覆盖且无场次重叠时，才按重叠时长建议权重。金额缺失、覆盖空档、并行直播均保留异常，由人工处理 |
| 月度费用分配 | 选择同月已确认的权重方案，复用给其他费用；每笔金额重新计算并保持守恒。预览时必须核对每笔费用的真实受益范围，不复制原笔分配金额 |

小时投流建议属于管理分摊，不表示取得了分钟级实际消耗。仅有账号和计划相同也不会自动确认最终分配；本月范围经人工确认后才可复用。没有通用平台适配层、模糊名称匹配或自动分摊兜底。

### 依据变化与历史版本

订单支付时间、目标场次、投流来源及关联范围、月度费用类别/金额等关键依据改变时，保留原决定并要求复核；重跑新候选不能消除旧决定的复核要求，需要重新人工确认。只补充月度费用说明文字时保留修改记录，不改变原分摊结果。

成本标准的单价或订单适用范围改变时，已补齐的成本不会静默跟随变化，关账要求复核。核对实际单价后可在该笔履约费用中更正；若原单价仍正确，勾选“已按实际依据重新确认当前单位成本”，明确转为人工实际成本。仅修改其他费用或改变单价书写格式不会丢失原标准来源。

M2关账副本增加原候选及异常、采用候选编号、成本标准、投流关联和批量修改记录。Excel仍为七张工作表，在核对明细与人工修改中展示这些依据。升级前M1版本没有的推荐信息不会补造；旧关账版本持续使用其原副本。首页只展开前30项关账问题，完整清单可下载。

## 月中先看经营利润，月末再关账

月度费用可以暂不录入：标准模板的“月度费用”表可留空，也可省略该工作表，其余五表保留。后续用标准模板补充导入月度费用，不会删除之前的数据。

步骤3点击“先看经营利润”，或在步骤4选择“月中经营利润（不含月度费用）”。程序仍检查订单归属、实际结算销售额、最终佣金、投流及商品履约成本；不检查月度仓储、人工、管理、损益税费和其他结算调整的分配状态。预览只展示净经营收入和经营复盘利润，不展示最终结算利润、不生成关账版本、不进入M3分析。

月度费用未录入表示待补充，不表示实际零元；已录入的月度费用和分配依据继续保留。若直接数据也未取得，预览仍会阻止金额展示，不用支付GMV或估计值填补。月末切换“完整费用核对与关账”，补齐月度费用并确认费用清单完整后，按原流程保存双利润和正式Excel。系统无法自动识别未录入的费用，清单是否完整仍由BP确认。

## 标准模板字段

模板见 `docs/templates/经营复盘标准模板.xlsx`；演练文件见 `docs/templates/经营复盘合成两场账例.xlsx`。也可执行 `python3 -m src.workbench.demo` 重新生成这两个文件，该命令不修改数据库。

标识符和单价建议按文本填写，尤其是长订单号、前导零和超过两位小数的单价。不得使用 Excel 公式，请粘贴为值。金额文本按 Decimal 解析，存储与汇总使用整数分，四舍五入为 ROUND_HALF_UP；商品成本先乘数量，最后舍入到分。

| 工作表 | 字段 | 要求与口径 |
|---|---|---|
| 场次 | 场次编号、达人、开播时间、结束时间 | 必填；场次编号唯一。自播也填写可识别名称。结束晚于开始；时间使用北京时间 `YYYY-MM-DD HH:MM:SS` |
| 订单行 | 订单号、子订单号或行号、SKU、数量、支付时间 | 必填；订单号+子订单号/行号作为业务键，数量为正整数；按支付时间人工归属 |
| 订单行 | 最终结算状态、最终结算日期 | 状态为“已结算”或“待结算”；关账要求已结算且有日期。日期为 `YYYY-MM-DD`，不得早于支付日期 |
| 订单行 | 确认结算销售额、平台费、其他未扣款 | 可暂缺，但关账前必须取得。销售额已经扣退款及取消，未扣后列平台费、达人费用和其他未扣款。不能填写净到账金额 |
| 订单行 | 原始成交额、退款额、取消额 | 可选核对字段；不参与二次扣减。源数据没有时保留空白，不伪造为0 |
| 投流 | 原始记录编号、账号、计划、小时起始、小时结束、金额 | 记录编号唯一；金额可暂缺，但有投流业务时取得消耗并确认分配后才可关账 |
| 商品与履约 | 订单号、子订单号或行号、单位成本 | 对应已有订单行；单位成本可以暂缺，关账时必需，不能填“不适用” |
| 商品与履约 | 出库数量、退回恢复库存数量、损坏退回数量 | 必填非负整数；退回合计不超过出库，出库不超过订单数量；损坏退回另计损耗 |
| 商品与履约 | 实际赠品费、实际运费险、实际物流费、退货损耗 | 记录实际费用。可选项目可填“不适用”，留空是未取得；赠品业务按场次声明，损坏退回存在时损耗必须为已取得金额 |
| 达人费用 | 场次编号、最终佣金、坑位费、达人调整、结算依据 | 场次编号唯一；达人/坑位业务适用时要求最终金额与结算依据。达人调整正数表示补付、负数表示追回，并在经营利润中扣减；无调整填0或不适用 |
| 月度费用 | 费用编号、月份、费用类别、金额、分摊依据及直播承担范围 | 费用编号唯一，可一类多笔；月份为 `YYYY-MM`。类别为仓储、人工、管理、损益税费或其他结算调整；范围与依据必填。分配目标须为同月场次 |

数量和普通费用不得为负。允许负数的是达人调整、其他结算调整；其他结算调整正数增加最终利润。金额单项及核算科目汇总上限为 999,999,999,999.99 元，超范围拒绝。

留空、实际零元、不适用保留为不同值。场次整体声明某项业务不适用后，无对应费用时明确按0计算，若存在非零费用会要求核对。运费险、物流等可在费用字段填“不适用”。月度费用统一维护，在关账时一次确认清单完整，不要求每场逐一重复确认17个科目。

## 核算与核对

$$
\text{净经营收入}=\text{确认结算销售额}-\text{平台费}-\text{其他未扣款}
$$

$$
\text{经营复盘利润}=\text{净经营收入}-\text{达人最终费用}-\text{投流费}-\text{商品与履约直接成本}
$$

$$
\text{最终结算利润}=\text{经营复盘利润}-\text{间接费用及损益税费分摊}+\text{其他结算调整}
$$

确认结算销售额中的退款、取消不再扣第二次。部分退款未退货仍保留销售成本数量。未发货取消的出库数量为0；退回恢复库存和损坏退回从销售成本数量中扣除，损坏计入单独损耗。已经发生的赠品、物流和保险不随退款归零。佣金采用最终结算金额；佣金基数依据协议，不从订单猜测。

共享费用仅输入直播应承担部分。权重由 BP 指定；按整数商计算，余数从大到小补分，同余数按场次编号排序。负调整先分配绝对值再恢复负号。每一笔源额均满足分配合计严格相等，尾差在 Excel 中保留。

利润率分母为净经营收入；结算销售额/投流费仅是关联表现比率，不代表投流因果增量。分母非正时显示“不适用”，负利润正常显示。税费采用 BP 已确认损益金额，系统不计算应纳税额。

Excel 分为四类内容，核对明细拆为七个实际工作表：管理摘要、场次损益、核对明细、分摊明细、人工修改、SKU与公共项目、版本与口径。金额与比率来自指定关账副本，不使用实时表或 Excel 公式重新算账。SKU只展示直接贡献，达人、投流、间接费用等公共项目单列，与场次最终利润核对。

## 两场合成账例演练

1. 在试用库选择2026-09，使用“新增直播场次”上传“经营复盘合成两场账例.xlsx”，13条来源记录应全部入账。下文S1/S2指文件来源编号；实际操作请使用页面映射生成的内部场次编号。

## 数据保护与后续试用

当前工作台数据库结构版本为3。首次打开结构版本1的 M1 工作台库，先用 SQLite backup API 保存同目录 `原库文件名.pre-m2-时间戳.bak`，再连续完成必要升级；版本2升级前保存`原库文件名.pre-daily-时间戳.bak`。升级失败回滚且保留备份，历史关账副本不重算。M3只读分析兼容结构版本2和3，但不会自行迁移数据库。旧 MCP 原型库仍拒绝连接。不要仅复制正在运行的主 `.db` 文件；恢复时先停止工作台，并保留当前库，再将选定备份复制为新的试用库启动核对。测试均使用临时库；本地数据库、备份、正式报表不进入代码提交。

下一步由财务 BP 使用脱敏实际数据验证处理质量：记录是否减少重复判断、筛选和录入；异常、人工修改及依据能否查全；采用相同业务决定时能否与历史关账金额一致。合成数据与容量测试不能替代真实业务验收。多人协作、平台原生格式适配、机器学习、ERP与只读Agent均不在本次M2范围。
