# 工作台轻量桌面版设计：pywebview＋Python

日期：2026-09-07。状态：实施中；已生成本机开发验证版，文件交互与BP试用待验收。

## 1. 目标与范围

把现有M2结算工作台和M3经营分析看板放进独立桌面窗口。用户双击应用即可使用，无须打开浏览器、输入网址或运行终端。

首版只支持当前使用的macOS和本机单用户，交付一个可双击运行的`.app`。窗口内继续使用现有“月份总览｜结算工作台｜经营分析”，包括导入、人工确认、关账、Excel导出、证据查询与条件测算。

原则是增加桌面外壳，复用业务系统：不重写页面、不改变公式、不建设聊天、登录、云同步、自动更新或多窗口。Windows打包在macOS实际试用通过后再讨论。

## 2. 最小架构

```text
桌面应用：一个Python进程
├── 主线程：pywebview原生窗口
└── 后台线程：现有WorkbenchServer（仅127.0.0.1）
    ├── M2页面与业务操作
    └── M3页面／只读API → AnalysisService → CloseReader
                         ↓
                 同一份本地SQLite账本
                         ↑
           独立stdio MCP → AnalysisService
                         ↑
                 Codex / Claude Code
```

pywebview加载现有本地HTTP地址，不使用`file://`加载业务页面，也不启用另一套内置HTTP服务。GUI事件循环运行在主线程，现有HTTP服务运行在后台线程；这是pywebview支持的本地服务接入方式。[官方架构说明](https://pywebview.flowrl.com/guide/architecture.html)、[主线程要求](https://pywebview.flowrl.com/api/#webview-start)

桌面端只依赖现有页面和应用服务，不启动MCP、不调用模型。MCP由客户端独立启动，桌面窗口关闭后仍可查询已有关账副本。

## 3. 启动、端口和退出

### 启动

1. 读取已保存的账本绝对路径；首次使用按第4节选择账本。
2. 取得该账本的工作台进程锁，检查路径和数据库类型，再调用既有初始化／升级入口；保留现有升级备份机制。
3. 创建`WorkbenchServer(('127.0.0.1', 0), db_path)`，由系统分配空闲端口。通过`server_port`取得实际端口，不先扫描再抢占端口。
4. 启动HTTP后台线程；以有超时的本机请求确认服务已就绪，再创建窗口并打开`/months`。建议窗口初始大小1200×800，可调整大小。
5. 出错时显示简短原因、重试方向和日志位置，不留下持续空白的窗口。初始化或窗口创建失败均释放服务、线程和锁。

端口只供应用内部使用，用户无需记忆。保留原浏览器CLI入口；其默认端口可以继续为8765，桌面模式不连接或接管一个来源不明的既有服务。

### 防止重复运行

首版采用macOS文件锁：对规范化账本路径对应的锁文件使用`fcntl.flock`，锁由工作台进程持有至退出。桌面与浏览器CLI启动均执行同一检查，MCP只读进程不取得此锁。

同一账本已有工作台运行时，显示“该账本已在工作台中打开，请使用已有窗口或先退出原工作台”，第二个进程退出。首版不做跨进程窗口唤醒。锁不等于SQLite事务，业务原子性仍由既有事务保证；升级前需先停止尚未接入此锁的旧工作台进程。

### 退出

关闭唯一窗口即退出应用，不留托盘或后台常驻服务。关闭请求先检查正在处理的业务请求；导入、确认、关账或导出尚在进行时取消此次关闭，提示操作结束后再退出，不强杀线程。

可以退出时先停止接收新请求，等待已接收请求结束，关闭监听并回收线程，最后释放锁和窗口。请求计数与进入退出状态的切换须同步，避免检查后又接受新写请求；复用现有连接超时处理空闲连接。异常退出依靠SQLite事务回滚，重启不自动重放上次POST操作。

## 4. 数据路径：选定一份账本，保持稳定

应用文件和账本分开存放，账本不得放入`.app`、打包临时目录或依赖当前工作目录。

首次打开提供两个简单选项：

- **使用已有账本**：通过原生文件选择框选择现有`workbench.db`，只保存其绝对路径，不复制或搬移。先只读检查它是支持的工作台库；旧ROI原型库明确拒绝，不能当作新版工作台库打开。
- **创建新账本**：在`~/Library/Application Support/LiveCommerceWorkbench/workbench.db`创建空账本；目标已有文件时不覆盖。

同目录的`desktop.json`只保存选定账本路径，不保存业务数据或模型密钥。之后直接使用该路径；路径丢失或不可写时提示重新选择，不悄悄创建另一份空库。首版不建设多账本切换管理；重新选择要求退出当前账本。

现有用户优先选择项目中的实际账本，避免首版额外做数据迁移。更新`.app`不影响外部账本和既有备份；用户自行移动账本后必须重新选择路径。

MCP的`--db`必须指向同一绝对路径。桌面菜单“数据位置”显示账本路径和接入说明；如选择了不同路径，在用户明确授权后更新客户端配置，不能自动修改用户级Codex／Claude配置。验收时对同一月份、版本核对桌面与MCP结果。MCP保持独立进程和既有只读工具权限。

## 5. 页面与文件操作

| 操作 | 首版处理 |
|---|---|
| 页面导航、筛选、比较、测算 | 复用现有HTML、GET/POST和M3共同契约 |
| 数据导入 | 复用现有文件输入框和上传流程，验证中文文件名及取消选择 |
| Excel、CSV和模板下载 | 复用现有下载响应与文件名，启用pywebview下载能力；验证保存位置选择、取消和同名文件处理 |
| 复制分析引用 | 先复用现有复制按钮；若WebKit剪贴板权限不兼容，保留选中文本后Cmd+C的明确回退提示 |
| 常用桌面操作 | 原生标题栏及最少菜单：回到月份总览、数据位置、退出；保留复制粘贴快捷键 |

pywebview默认禁用下载，需明确启用`ALLOW_DOWNLOADS`并实测macOS行为。[官方下载设置](https://pywebview.flowrl.com/api/#webview-settings)

文件保存是桌面验证的优先项。若所选版本无法可靠保存现有下载响应，先解决该兼容点，再进入打包；不以“复制网址去浏览器下载”作为成品验收通过。需要补适配时，只包装固定的现有导出能力与原生保存对话框，不创建通用文件读写桥，不改导出数据和核算逻辑。

## 6. 保持现有边界

- 服务仍只监听`127.0.0.1`，保留动态端口对应的Host/Origin校验、M2 CSRF与现有CSP，不因放入桌面窗口而关闭这些检查。
- 首版不向页面暴露通用Python、Shell或文件系统接口，不设置业务`js_api`。外部链接不作为应用内部业务页面加载，不加载远程脚本。
- 桌面启动可执行既有M2初始化／升级；启动后的M3页面、测算和JSON API仍须在工作台写连接前分派，仅经`CloseReader`读取关账副本。
- 两套利润、整数分、舍入、分摊、人工确认、关账历史和测算假设边界全部继承现有实现。条件测算仍不落库，历史版本不自动切换。
- M2/M3结构化功能本地运行，不依赖模型或互联网；Codex／Claude是否联网由所选客户端和模型决定。

日志仅记录启动、退出和错误诊断，建议使用一个有大小上限的轮转日志文件；不记录整份订单、费用备注或数据库内容。不增加日志平台。

## 7. 打包方案

macOS首版优先使用`py2app`，这是pywebview官方给出的macOS打包路径。[官方打包说明](https://pywebview.flowrl.com/guide/freezing.html)

在隔离构建环境中验证Python、pywebview、PyObjC和py2app的兼容组合后锁定版本；不直接假设用户当前Python 3.14能完成打包，也不为桌面外壳升级全部业务依赖。

交付自带Python运行环境与所需库的`.app`，首版只构建当前Mac的处理器架构，明确记录支持的系统和架构。把模板等实际运行资源纳入包中，使用包资源路径读取；禁止把正式数据库、导入文件、测试输出或用户配置一起打包。

先完成本机试用版，不建设安装向导、自动更新或通用安装器。对外分发时再完成Apple签名、公证及干净机器验证；未完成前不声称可在任意Mac直接运行，也不要求关闭系统安全保护。

## 9. 验收标准

1. Finder双击`.app`进入月份总览，不依赖启动终端、项目工作目录或手工运行服务。
2. 在隔离合成账本完成导入、归属确认、费用维护、关账、正式Excel保存和再次打开；中文路径和取消文件对话框可用。
3. 桌面中完成M3概览、重点场次、证据、两类比较及费用／SKU测算；同范围、同版本的金额与MCP及正式关账结果一致。
4. 所选账本重启后保持一致；缺失路径不新建替代库；替换应用包后原账本和历史版本保留。
5. 同账本第二个工作台进程被拒绝；正常退出后端口和锁释放，MCP只读查询不被误关闭。
6. 启动失败可诊断；忙碌时退出不会截断写操作；旧工作台浏览器模式继续通过回归。
7. M3读请求仍绕过写连接，测算不改数据库；下载Excel与原报表逐单元格核对，无需比较含生成元数据的文件字节是否完全相同。
8. 记录实际验证的macOS、CPU架构和依赖版本。无开发环境的运行验证未完成时，只能标记为开发验证版；BP试用未完成时单独注明待验收。

完成标准是一个可靠的本地桌面入口。首版不增加智能化能力、多人共享或新核算功能；这些需求分别沿用各自设计，不混入桌面封装。
