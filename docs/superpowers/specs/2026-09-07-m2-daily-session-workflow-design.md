# M2日常场次处理设计

日期：2026-09-07。状态：已实施并通过合成数据与浏览器验证；仍待财务BP脱敏真实数据验收。

## 背景与目标

BP按日新增直播并分批补充订单、履约和结算数据；现有界面按月累计展示，容易混淆本次新增数据与历史已确认记录。用户确认本轮设计四项：新增/补充入口、订单归属表达与单场操作、多SKU成本维护、月度分摊辅助入口整理。

本轮不包含抖音/千川原生文件适配，不接模型，不调整利润公式、月中预览的直接数据要求或正式关账规则。设计中的交互与功能均为拟实现行为，不作为已交付能力。

## 共同工作范围

- 月份继续用于汇总和关账；日常操作围绕选择的场次和本次导入展开。
- 页首持续显示业务月份、当前场次/多场范围、当前操作（新增/补充）、本次导入文件和处理范围。金额、待办数和批量操作各自标明覆盖范围。
- 提供“本次导入待办 / 所选场次全部 / 本月全部”切换。导入成功后默认进入本次新增、更新和需复核记录；旧记录未变单独列示，不计为新完成事项。
- 导入批次不等于直播场次：一场可多次导入，一次导入可涉及多场。文件上传也不自动确认订单归属或业务适用性。
- 本次导入清单须保留新增、更新、未变、冲突的记录身份和来源引用；不能只依据业务记录当前的batch_id还原历史批次成员，因为后续更正会改变该字段。
- 所有批量预览固定具体记录及旧值；确认时复核范围、来源、月份状态与相关规则，变化则要求重新预览。页面筛选不能扩大实际写入范围。
- 所选场次的处理状态不替代全月关账检查。跨场次或跨月记录必须显式列出，不自动重新归属。

## 一、入口：新增直播场次 / 补充或更正已有场次

### 页面

数据导入顶部提供两个操作卡片，用户先明确意图，再上传和核对文件。

**新增直播场次**

1. 填写或从文件预填达人/自播名称、开播和结束时间；用户确认场次资料。
2. 系统生成唯一内部场次编号，显示易读的日期、时段与达人名称。编号在预览期间固定，重复提交不得生成重复场次。
3. 文件自带场次编号时保留原始标识，并在预览展示与新内部编号的对应关系。新映射只作用于本次明确的新场次及其场次引用，不改写历史记录或订单业务键。
4. 旧编号与已有场次冲突时，展示已有场次信息和新资料：用户需确认是新场次还是补充旧场次；不按旧编号静默沿用业务确认。
5. 若达人及时间与已有场次疑似重复，提示核对，不仅因为生成了新编号就允许重复建场。并行直播等合理情况可说明依据继续。
6. 新场次不继承旧场次的订单归属、费用确认或投流分配；月度成本标准只能作为后续可选参考。

新场次与文件入账原则上在最终确认时一并完成；预览/取消不留下半建场次。多场文件逐一展示场次映射，不能全部套用一个目标场次。

**补充或更正已有场次**

1. 通过日期和达人选择已有场次；混合文件可明确选择多个已有场次。
2. 上传文件后分组展示：新增记录、已有未变、变更待确认、场次/业务键冲突。
3. 原订单号及子订单号保持不变。相同键、相同内容只跳过重复；内容变化展示前后差异并要求原因。
4. 场次选择是处理范围，不是把文件内全部订单重新绑定到目标场次的授权。已归属其他场次的数据单独提示，默认保持原归属。
5. 关键依据变更触发已有规则的复核；资料未变则不要求重复确认。已关账月份需明确走现有重开流程，不由导入自动重开。

### 冲突原则

- 新增模式下发现已有订单号，不能自动改号或复制订单。未变旧订单可明确排除在本次新增之外；已有订单更正应转入补充流程。
- 同一订单重复导出与误用模板中的旧编号需区别展示；不能通过清空账本或强制换订单号解决。
- 导入总结用“本次新增/更新/未变/需处理”描述，不把整月累计完成数当作本次进度。空新增批次明确提示“没有新增数据”，并提供查看跳过/冲突原因。

## 二、步骤2：确认订单属于哪场

### 名称与说明

标题改为“确认订单属于哪场”。说明：“决定订单销售额及对应商品履约成本计入哪场直播；确认前可以核对和修改。”

### 单场文件

- 提供“本文件订单属于同一场”的明确选择，并展示选定场次名称和时间。
- 默认选中本次新增、尚未归属且无冲突的订单；展示记录数、日期范围和例外。
- 主操作为“预览并确认到本场”。用户不必先生成时间候选。
- 已归属其他场次、需复核或时间异常记录单列。时间异常不直接证明归属错误，用户可依据运营记录明确人工归属并留理由。
- 最终预览展示订单及原/新场次，确认后仅处理预览清单。批量选择不默认覆盖旧决定。

### 多场混合文件

- 若有明确且经过确认的来源场次映射，先按该映射展示核对结果；仅选择了某个工作场次不构成来源映射。
- 无明确标识时，提供“按直播时间匹配”，继续复用固定规则。
- 分为“匹配明确待确认”和“需要人工判断”；后者包含无匹配、并行场次、时间边界及依据变化等。
- 主操作为“批量确认匹配明确的订单”；异常逐笔或按相同依据批量选择场次。
- “已确认”单独可查。零待办时提示本次已完成，而不继续展示空操作表单。

## 三、多SKU成本表

将单SKU录入表替换为根据当前处理范围的订单自动汇总的成本表，默认仅展示相关SKU，保留切换所选场次/本月范围的能力。

| 列 | 内容 |
|---|---|
| 选择 | 勾选本次维护的SKU |
| SKU | 来源精确标识，不要求用户重新输入 |
| 已有实际成本 | 已填订单数量及不同单价情况；多价不强行合并 |
| 本月参考标准 | 已确认标准及依据，无标准显示待维护 |
| 本次单位成本 | 每个SKU独立输入金额 |
| 适用范围与依据 | 默认本次所选订单，明确说明来源；可填写共同依据及行级例外 |
| 待补数量 | 空缺单价、缺少履约记录等分别提示 |

操作：“预览本次成本补齐”→展示每个SKU的影响记录→“确认保存并补齐”。多SKU一次处理，不需要逐SKU保存、跳回、再预览。

规则：

- 默认只补齐预览范围内已有履约记录的空缺单价；已有实际成本、出库数量、退回数量和其他费用保持原值。
- 缺履约记录时显示“需补履约数据”，不凭订单数量创建或猜测实际出库、退回数量。
- 本次填写默认仅应用于明确订单范围。是否另存为“本月通用成本标准”需明确选择及适用依据，不能因操作在月度页面就自动应用整月。
- 选择另存月度标准时，复用现有精确SKU+业务月份标准机制；如标准已存在，展示差异与受影响历史来源，沿用既有复核规则。已关账月份不允许修改。
- 多价SKU可下钻到订单行核对；本轮不扩展完整采购批次成本核算。
- 标准保存及成本补齐在同一确认事务内执行，部分失败整批回滚；确认前发现记录已被修改则要求重新预览。
- 金额精度、舍入规则和来源追溯继续复用现有核心。表格汇总和影响数量由程序生成。

## 四、月度分摊中的“沿用已有分摊方式”

- 从任务3A移除参考费用相关控件。3A保留场次业务范围及投流关联；商品成本单独以明确标题展示。
- 在月度费用分摊区域提供折叠辅助功能“沿用已有分摊方式”，与投流分配清楚区分。
- 只有本月存在有效、已确认、按权重分配且无需复核的参考费用，并有其他可作为目标的费用时，才显示该操作入口。
- 月度费用暂不录入时展示“月度费用可后补”，不展示空下拉框。存在月度费用但无可复用方式时，提示“先完成一笔费用的权重分摊，再用于其他费用”。
- 选择参考费用后，展示其受益场次、权重与依据；目标列表排除参考费用自身，已有分配的目标默认不选中。
- 仅复用受益范围和权重，不复制金额；每笔目标费用按自身源额计算，分别展示分配结果及尾差。
- 目标费用承担范围是否相同由BP确认。来源金额或规则变化后须重新预览；原分配若需更正，明确说明并留痕。
- 按明确金额分配的记录暂不作为权重复用来源，不擅自推导新的权重。

## 典型走查与验收场景

1. 昨天场次已完成，今天导入新场次：生成新内部编号，只显示今日新增待办，旧场次结果与确认记录保留。
2. 今天模板误用昨天场次编号：确认前明确提示冲突，不能默认为昨天的更新；真实平台订单号不得被自动改写。
3. 重复导出历史订单：未变记录不重复入账；退款/结算信息变化按原键更正，保留前后值及必要复核。
4. 同一场先导订单、后补履约与佣金：继续挂接同一场，分别显示本次变化；本次批次与场次整体进度可区分。
5. 单场订单无需生成时间候选即可批量核对确认；混合多场不会被默认全部归入当前场次。
6. 多个SKU同时输入不同单位成本：只更新明确范围的缺失单价；实际成本不覆盖，缺履约数据仍可见；失败不会部分保存。
7. 未录月度费用或无有效权重方案：不出现空参考下拉框；有有效方案时才能展开复用，源额逐笔守恒。
8. 页面筛选、预览后导入更新、重复点击提交、已关账及重开等情况下，批量写入范围不扩大，旧版本和正式计算结果可核对。

## 待实施时需落实的边界

新增场次预览、来源编号映射、批次成员和多SKU确认需要明确的服务端结构与验证；不能只靠前端筛选或文案保证。沿用现有导入、人工确认、原子批量操作、来源留痕和关账机制，按必要程度增加存储，不另建核算体系。

平台原生格式接入待脱敏样本另行设计，不因本次入口改版宣称已支持抖音/千川原始文件。

## 2026-09-07 实施记录

- 数据库结构升级为版本3，新增不可变的`batch_members`批次成员清单和`session_source_mappings`来源场次映射；后续更正即使改变业务记录当前`batch_id`，历史批次仍可按记录身份查询。
- 导入页已提供“新增直播场次 / 补充或更正已有场次”入口。新增模式为每个文件场次生成稳定、易读的内部编号，来源编号只在本批次映射；来源编号冲突或达人时间疑似重复时，必须明确确认并填写依据。新增模式发现已有订单内容变化会拒绝并引导转入补充流程。
- 订单页改为“确认订单属于哪场”，支持本次导入、所选场次和本月范围；本次导入还能切换新增/更新、未变旧记录和全部成员。单场主操作直接预览确认，多场文件继续使用固定时间规则，异常与已确认记录保持分离。
- SKU成本改为按当前订单范围自动汇总的多SKU表。一次预览可为不同SKU填写不同单位成本，只补齐已有履约记录中的空缺单价；缺履约记录、已有实际成本和多价情况单独展示。可明确选择同时保存月度标准，标准与成本补齐在一个事务中确认，失败整批回滚。
- 月度权重复用已从任务3A移到共享费用分配区域。没有月度费用时只提示可后补；没有有效权重来源时给出下一步；存在有效来源和其他目标费用时才显示入口，并展示受益场次、权重与依据。
- 核算公式、月中经营利润要求、正式关账规则和M3八工具契约未改变。M3只读端兼容结构版本2和3的关账副本。
