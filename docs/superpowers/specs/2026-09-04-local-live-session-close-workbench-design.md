- 首版Excel优先交付管理摘要、场次损益、核对明细、版本与口径；十页细分分析是后续扩展目标。

## 1. 产品定义

第一阶段建设面向财务 BP 的本地经营复盘工作台，以关账数据为唯一分析基础。系统负责数据处理、场次归属、成本核算和 Excel 管理报表生成；Agent 作为只读分析助手，负责基于已确认数据进行查询、归因和经营建议，不参与财务数据修改和核心计算。

公司主营学习机，销售平台以抖音为主，直播业务包含达人合作、坑位费、佣金和千川投流。系统以单场直播为最小分析对象，同时通过结算期间完成间接费用分摊与批量关账。

第一阶段由一名财务 BP 维护全部数据。业务负责人、管理层、运营和投放团队只提供源数据或接收报表，不进入系统协同录入。

## 2. 目标与非目标

### 2.1 目标

- 形成可审计、可重算、可追溯的单场直播财务结果。
- 支持达人合作、投放预算、商品策略、直播排期和成本结构五类经营决策。
- 自动处理可唯一判断的场次归属，同时让财务 BP 审核并处理歧义。
- 生成适合管理层和业务团队使用的 Excel 管理报表。
- 让 Agent 在严格只读边界内完成查询、差异解释和经营建议。
- 保证同一输入、同一规则版本和同一成本版本得到相同结果。

### 2.2 非目标

第一阶段不建设：

- 实时利润预测或直播过程监控；
- 多人账号、权限、审批流或云端协作；
- 用友 ERP API 自动对接；
- 自动生成 PowerPoint；
- 机器学习归因模型；
- 由 Agent 修改数据、选择归属或执行关账。

## 3. 总体架构

系统由五个边界清晰的模块组成：

1. **数据接入与质量模块**：接收源文件、记录导入批次、执行质量校验，并将异常记录隔离。
2. **场次归属模块**：通过可配置规则产生场次推荐，支持财务 BP 审核和人工调整。
3. **核算与关账模块**：维护成本与费用池，执行确定性核算，完成关账、重新开账和版本管理。
4. **报表模块**：从关账快照生成 Excel 管理报表。
5. **Agent 查询模块**：仅从关账快照和确定性分析视图读取结果，向 Agent 提供只读查询。

本地工作台采用轻量网页界面，运行在财务 BP 的电脑上。业务逻辑不得写入界面代码；界面、Excel 报表和 Agent 查询服务共同调用同一组领域服务。SQLite 负责本地存储，数据库迁移采用显式版本管理。

建议的代码边界为：

- `domain`：财务实体、状态和业务规则；
- `ingestion`：文件适配、标准化、导入批次和数据质量；
- `attribution`：规则配置、系统推荐和人工归属决定；
- `closing`：成本、分摊、核算、关账和版本；
- `reporting`：Excel 报表生成；
- `agent_query`：只读分析查询；
- `workbench`：本地操作界面。

## 4. 数据接入与质量闸门

### 4.1 数据来源

第一阶段接收以下数据：

- 直播场次：达人、开播时间、结束时间及场次说明；
- 抖音订单及最终结算明细；
- 千川小时级消耗明细；
- 达人合作协议参数和最终结算单；
- SKU 单位成本、赠品成本、运费险和订单物流费；
- 月度仓储、人工、管理费用和税费费用池。

系统只导入核算所需字段，不保存客户姓名、电话、地址等个人信息。

### 4.2 导入批次

每次导入生成不可变批次记录，包含：

- 数据来源类型；
- 原始文件名和文件哈希；
- 导入时间；
- 表头映射版本；
- 原始行数、接收行数、隔离行数和金额汇总；
- 批次状态和处理结果。

相同文件哈希不得重复导入。订单明细、投流明细和结算记录同时使用业务主键执行幂等校验，避免内容相同但文件名不同导致重复入账。

### 4.3 质量校验

校验分为三个等级：

- **阻断错误**：缺少业务主键、必填金额无法解析、退款超过允许范围、汇总金额不平或关键日期无效。记录进入隔离区，不得入账。
- **待确认警告**：未知 SKU、达人名称无法标准化、金额显著偏离历史范围或场次候选不唯一。数据可以暂存，但不得关账。
- **提示**：非关键字段缺失或轻微格式差异，不影响核算。

质量检查至少覆盖：

- 字段完整性、类型和日期格式；
- 文件级和业务记录级重复；
- 负金额、退款异常、佣金异常和投流突变；
- 未知 SKU、未知达人和缺少直播时间；
- 明细汇总与平台报表汇总行的一致性。

每个问题必须记录数据位置、问题原因、处理方式和处理结果。导入使用数据库事务，阻断错误不得造成部分入账。

## 5. 场次归属

### 5.1 可配置规则评分

第一阶段使用轻量、透明、可配置的规则评分，不使用机器学习或复杂预测模型。规则可包含：

- 达人名称或达人 ID 一致；
- 订单支付时间位于直播时间窗口；
- 千川小时消耗与直播时间重叠；
- 投放计划已绑定达人或特定场次；
- 同一时间存在多个候选场次；
- 记录处于开播前后缓冲区；
- 关键匹配字段缺失。

规则权重、时间缓冲和处理阈值通过版本化配置维护。规则得分只用于排序和分流，不代表统计置信度。

### 5.2 系统推荐记录

每次规则运行生成不可变的系统推荐记录，包含：

- 源记录和候选场次；
- 每个候选场次的规则得分；
- 命中的规则和匹配依据；
- 冲突或未选中原因；
- 规则版本和生成时间。

处理结果分为：

- 自动推荐：推荐结果唯一且规则得分达到自动处理区间；
- 待人工审核：存在多个接近候选、边界时间或待确认警告；
- 异常处理：缺少关键字段或没有有效候选。

自动推荐不会直接成为已确认归属。财务 BP 可以逐条审核，也可以在查看规则版本、匹配汇总和异常清单后批量确认。只有完成审核的系统推荐或有效人工决定才能进入关账。任何未处理的待审核或异常记录均阻断关账。

### 5.3 人工决定与优先级

财务 BP 的人工决定独立保存，不修改或覆盖系统推荐。人工决定包含：

- 最终归属场次；
- 确认推荐、修改推荐或指定异常记录的操作类型；
- 修改原因、参考凭证或备注；
- 操作时间；
- 被替代的上一人工决定。

有效归属优先级为：最新有效人工决定高于已审核系统推荐，已审核系统推荐高于未审核系统推荐。重新运行规则只能生成新的推荐版本，不得覆盖人工决定。

改变已人工确认的归属时，必须撤销旧决定并新增调整记录。关账快照同时锁定系统原始推荐、人工决定和最终有效归属。

## 6. 数据模型

核心实体包括：

- `live_session`：直播场次主数据；
- `creator`：达人标准主数据；
- `sku`：商品标准主数据；
- `import_batch`、`import_record`、`validation_issue`：导入和质量记录；
- `order`、`order_line`：订单头与商品行；
- `ad_spend_hourly`：小时级投流事实；
- `creator_contract_version`、`creator_settlement`：达人合同和最终结算；
- `sku_cost_version`：带生效期间的 SKU 成本；
- `indirect_cost_pool`、`allocation_rule_version`：间接费用池和分摊规则；
- `attribution_recommendation`：不可变系统推荐；
- `attribution_decision`：不可变人工决定；
- `close_run`、`close_snapshot`、`snapshot_input_ref`：关账批次、结果和输入引用；
- `report_export`：报表版本和输出位置。

订单以订单号和子订单号或商品行号组成业务主键。商品成本使用实际结算数量，不再假设一行订单等于一件商品。

## 7. 核算口径

### 7.1 收入口径

$$
\text{确认结算销售额}
=
\text{成交金额}
-\text{取消金额}
-\text{退款金额}
$$

$$
\text{净经营收入}
=
\text{确认结算销售额}
-\text{平台技术服务费}
-\text{商家承担优惠及其他平台扣款}
$$

成交 GMV 只作为运营参考，不直接作为利润收入。利润核算采用平台最终结算数据。

### 7.2 经营复盘利润

$$
\begin{aligned}
\text{经营复盘利润}
={}&\text{净经营收入}\\
&-\text{达人最终佣金}\\
&-\text{坑位费及达人结算调整}\\
&-\text{归属投流费}\\
&-\text{SKU 商品成本}\\
&-\text{赠品成本}\\
&-\text{运费险}\\
&-\text{订单物流费}\\
&-\text{退货损耗}
\end{aligned}
$$

经营复盘利润用于评价达人、投流、商品组合和直播排期本身是否创造价值。

已退回并恢复库存的学习机不重复计入销售成本；退货物流和无法二次销售损耗单独计入退货损耗。赠品以实际发出为准，即使主商品退款也保留实际赠品成本。

### 7.3 最终结算利润

$$
\begin{aligned}
\text{最终结算利润}
={}&\text{经营复盘利润}\\
&-\text{仓储费用分摊}\\
&-\text{人工费用分摊}\\
&-\text{管理费用分摊}\\
&-\text{税费分摊}\\
&+\text{其他结算调整}
\end{aligned}
$$

两套利润均基于最终数据，不属于实时预测。区别仅在于是否纳入间接费用、税费和财务结算调整。

税费不得使用“税前利润乘综合税率”的简化算法。第一阶段将实际税费作为月度费用池导入并按税基或确认结算销售额分摊。企业所得税默认不计入单场经营评价；如管理口径要求展示，应作为独立费用池列示。

## 8. 分摊与结算期间

推荐默认分摊规则为：

- 仓储费用按实际出入库件数或仓储作业量分摊；
- 共享人工优先按实际投入工时分摊，无工时时按直播时长分摊；
- 管理费用按净经营收入占比分摊；
- 税费按相应税基或确认结算销售额分摊；
- 无法直接归属的投流按时间重叠规则分配，不按 GMV 静默分摊。

每个费用池必须满足：

$$
\sum_{i=1}^{n}\text{场次分摊金额}_i
=
\text{当期费用池总额}
$$

系统记录分摊规则、分母、原始计算值、舍入差额和人工调整。舍入尾差通过明确的尾差调整记录处理。

由于仓储、人工、管理费用和税费通常按月取得，最终结算采用月度批次关账，关账结果按直播场次展示。月度费用池不完整时不得生成最终关账版本。

## 9. 关账、版本和重新开账

场次数据经历以下状态：

$$
\text{数据待校验}
\rightarrow
\text{归属待确认}
\rightarrow
\text{费用待补全}
\rightarrow
\text{可关账}
\rightarrow
\text{已关账}
$$

关账前必须通过以下检查：

- 订单和投流明细已与源报表汇总核对；
- 所有收入和成本记录都有已确认归属；
- 达人最终结算单完整；
- SKU 成本和直接履约成本完整；
- 间接费用池与分摊规则完整；
- 分摊费用总额与费用池一致；
- SKU 利润合计与场次利润一致。

每次关账生成不可变快照，包含：

- 输入批次和文件哈希；
- 系统推荐、人工决定和最终有效归属；
- 达人合同与结算版本；
- SKU 成本和费用池版本；
- 分摊规则和计算规则版本；
- 两套利润结果、核心指标和关账时间。

已关账快照不得直接修改。重新开账必须填写原因，旧快照继续保留并标记为已被后续版本替代。重新关账生成递增版本，例如 `V1`、`V2`。默认报表和 Agent 查询使用最新有效版本；历史版本只能在明确的版本审计查询中使用。

## 10. 核心指标与历史基准

报表至少提供：

- 收入质量：成交 GMV、确认结算销售额、退款率和平台扣费率；
- 盈利能力：经营复盘利润、最终结算利润和两种利润率；
- 达人表现：达人费用、达人费用率、合作后经营利润和历史场次排名；
- 投流表现：投流金额、确认结算 ROAS、投流占比和投流后贡献利润；
- 商品表现：SKU 销量、退款率、单品贡献利润和利润贡献占比；
- 排期效率：每小时确认收入、每小时利润和同时间段历史表现；
- 成本结构：商品、履约、达人、投流和间接费用的金额与利润侵蚀比例。

$$
\text{确认结算 ROAS}
=
\frac{\text{确认结算销售额}}{\text{归属投流费}}
$$

该指标只表示归属效率，不宣称投流产生了因果增量。

系统不预设达人淘汰线或投流硬阈值。历史基准采用已关账场次的滚动中位数、分位数和趋势。比较结果必须说明样本量、日期范围和可比条件；样本不足时只展示事实，不产生强结论。

## 11. 本地工作台

工作台包含六个功能区：

1. 数据导入；
2. 数据质量；
3. 场次归属；
4. 费用与分摊；
5. 关账中心；
6. 报表中心。

首页优先展示待办事项，而不是泛化仪表盘，包括待处理质量问题、待审核归属、待补达人结算、未完成费用池和可关账期间。

工作台是唯一财务写入入口。第一阶段无需登录，启动后只监听本机地址，不对局域网或公网开放。

## 12. Excel 管理报表

每个结算期间生成一个带关账版本的 Excel 文件，包含：

- 管理层摘要；
- 场次损益；
- 达人分析；
- 投流分析；
- 商品分析；
- 排期分析；
- 成本结构；
- 数据质量；
- 归属审计；
- 口径与版本。

管理层摘要采用一页式打印布局，展示核心结论、主要变化、异常场次和待决策事项。报表中的每个金额必须来自关账快照，且工作台结果、Excel 明细和汇总保持一致。

## 13. Agent 只读分析

Agent 仅连接专门的只读查询接口。写入、归属、成本维护、重新开账和关账接口不向 Agent 注册，权限边界不依赖提示词保证。

Agent 只能使用已确认并已关账的数据。默认读取最新有效关账版本，并在回答中注明：

- 关账版本；
- 数据截止时间；
- 使用的经营复盘利润或最终结算利润口径；
- 样本范围和限制。

所有金额、差异、排名、分位数和趋势均由确定性查询服务计算。Agent 只负责组织语言、解释原因和提出经营建议，不自行补数或完成核心财务计算。

标准回答结构为：结论、数据证据、原因解释、建议动作、数据范围与局限。Agent 必须区分已核算事实、基于历史数据的分析和经营建议。对于未关账场次，Agent 只说明尚不可用于正式分析及缺少的关账条件。

## 14. 可靠性与异常处理

- 数据库迁移前自动备份；
- 导入和关账采用事务，失败时整体回滚；
- 异常记录保留原始值、异常类型和处理历史；
- 关键操作写入本地审计日志；
- 报表文件包含期间、关账版本和生成时间；
- 数据库、备份和报表路径可配置；
- 无法解析的数据不得通过默认零值进入利润计算。

## 15. 测试与验收

测试以业务风险为中心，覆盖：

- 导入、字段映射、幂等和质量校验；
- 规则推荐、人工优先级和历史保留；
- 财务公式、退款成本处理和跨层勾稽；
- 费用池守恒和尾差处理；
- 状态流转、关账、重新开账和版本追溯；
- 快照不可变；
- Excel 内容、格式、公式和可打开性；
- Agent 只读权限及关账数据边界；
- 使用真实脱敏样本的端到端流程。

核心验收条件为：

- 相同输入和规则版本产生相同结果；
- 重复数据不会重复入账；
- 人工决定优先且不覆盖系统推荐；
- 已关账结果不可静默变化；
- 分摊金额完整回勾费用池；
- SKU、场次、期间和报表层层勾稽；
- Excel 与关账快照完全一致；
- Agent 无法读取未关账数据或执行任何写入；
- 每项异常均能定位、解释和处理。

## 16. 第一阶段完成定义

第一阶段完成时，一名财务 BP 能够在本机独立完成以下闭环：

1. 导入一整个结算期间的脱敏真实数据；
2. 处理质量问题和重复记录；
3. 审核并锁定每笔收入和成本的场次归属；
4. 维护达人结算、直接成本和间接费用池；
5. 完成月度批次关账并保留版本；
6. 生成可直接用于管理复盘的 Excel 报表；
7. 使用 Agent 查询已关账结果、分析原因并形成经营建议；
8. 对任一报表金额追溯至关账版本、归属依据和来源记录。

## 17. 实施分解

第一阶段作为一个完整产品目标管理，但实施按以下可独立验收的纵向切片推进：

1. **核算底座**：新数据模型、数据库迁移、确定性双利润引擎和勾稽测试；
2. **可信导入**：导入批次、幂等、数据质量闸门和异常隔离；
3. **场次归属**：可配置规则评分、审核队列、人工优先级和历史保留；
4. **关账闭环**：费用池、分摊、月度关账、重新开账和不可变快照；
5. **管理交付**：本地工作台完整流程和 Excel 管理报表；
6. **只读 Agent**：确定性查询服务、只读 MCP 工具和经营分析回答约束。

每个切片必须通过自身业务验收后再进入下一切片。旧原型中的代码只有在符合新数据模型、核算口径和审计要求时才复用，不以保持旧接口兼容为优先目标。
