# M1 标准模板到Excel最小闭环实施计划

> 使用 `superpowers:executing-plans` 在当前会话逐项实施。复用现有Python项目，先交付可试用流程，不先建设独立基础设施平台。

**Goal:** 一名财务BP用两三场标准模板数据完成导入、人工归属、双利润、关账和Excel复盘。
**Architecture:** 本地单页工作台调用确定性业务函数；SQLite保存来源、修改记录和关账副本。M1不接入Agent。
**Tech Stack:** Python 3.11+、SQLite、Decimal、pytest、现有openpyxl；本地界面选用轻量方案，在界面任务开始时验证安装与本机运行。
**Spec:** `../specs/2026-09-04-local-live-session-close-workbench-design.md`；本次减重范围以 `2026-09-05-workbench-roadmap.md` 为准。

## Global Constraints

- 精确金额、经营复盘利润、最终结算利润及分摊金额守恒必须保留。
- 费用缺失与0元不同；可选项目允许“不适用”，不要求17项逐一确认。
- 同一笔退款或费用只扣一次。
- 已关账内容不能覆盖；人工修改记录保留旧值、新值和原因。
- 只实现本地单人操作；不建设通用会计分录、输入指纹、事件回放和复杂迁移。
- 旧库和旧原型保留，新工作台不用旧MCP写入工具。
- 所有自动测试使用临时目录或内存库，不修改用户数据库。
- 任务勾选依据2026-09-05实际实现与验证；尚无真实脱敏数据的试用项保持未完成。

## Task 1：标准模板与可信导入

**文件：** `src/workbench/db.py`、`src/workbench/imports.py`、`tests/test_workbench_imports.py`、模板和使用说明。
**交付：** 先提供标准Excel模板；各工作表的金额为人民币元，来源引用包含批次与行号。

模板分为以下工作表：

- 场次：场次编号、达人、开播/结束时间。
- 订单行：订单号、子订单号/行号、SKU、数量、支付时间、最终结算状态/日期、确认结算销售额、平台费及其他未扣款。
- 投流：账号、计划、小时起止、金额及原始记录编号。
- 商品与履约：订单行键、单位成本、出库及退回数量、实际赠品、运费险、物流和退货损耗。
- 达人费用：场次、最终佣金、坑位费、达人调整及结算依据。
- 月度费用：月份、费用类别、金额及分摊依据。

确认结算销售额已经扣退款和取消，但未扣后列费用。模板记录原始成交、退款及取消作为核对字段，不在引擎再次扣除。未发货取消订单不计销售商品成本；部分退款不等于退回数量。

## Task 3：精确金额、双利润及分摊守恒

**文件：** `src/engine/session_profit.py`、`tests/test_workbench_profit.py`。
**交付：** 无数据库和模型调用的确定性核算函数。

计划接口：

- `money_to_cents(text: str) -> int`：十进制文本转分，ROUND_HALF_UP；非法、NaN、无穷和超范围拒绝。
- `calculate_session(amounts: dict[str, int]) -> dict[str, int | str | None]`：已通过完整性检查的场次金额；返回科目合计、净收入、双利润及比率。
- `allocate_cents(total: int, weights: dict[str, int]) -> dict[str, int]`：非负整数权重，正负金额均守恒。
- `calculate_product_cost(unit_cost: str, retained_units: int) -> int`：Decimal单价乘实际计成本数量，最后舍入到分。

`amounts` 是固定报表分类，不是通用会计分录。输入科目缺少或类型错误必须拒绝；不适用项目由费用完整性检查明确映射为0并记录在费用表，不由引擎默默补齐。

比率返回十进制字符串或None；分母非正时为None，展示为不适用。整数金额严格拒绝布尔值和浮点数。

计算关系：

$$
\text{净经营收入}=\text{确认结算销售额}-\text{平台费}-\text{尚未扣过的商家优惠及其他平台扣款}
$$

$$
\text{经营复盘利润}=\text{净经营收入}-\text{达人最终费用}-\text{投流}-\text{商品和履约直接成本}
$$

$$
\text{最终结算利润}=\text{经营复盘利润}-\text{间接费用及已确认损益税费分摊}+\text{其他结算调整}
$$

- 普通费用为正数扣减；达人补付调整为正、追回为负并扣减；其他结算调整为正增加最终利润。更正输入记录即可，不建设分录冲销链。

退款、成本细则：恢复库存的退回商品从计成本数量扣除；损坏退回部分转为独立损耗，不重复计商品成本。部分退款未退货仍保留商品成本。赠品、物流和保险按实际费用，不随退款自动归零。

- [x] 写入金额精度、非法金额、一单多件、退货与损耗、负利润、缺失费用和零分母测试。
- [x] 使用此确定账例验证双利润：销售9,000元，平台费300元，达人佣金900元、坑位费500元、投流1,200元、商品4,000元、赠品100元、保险30元、物流100元、损耗50元；仓储100元、人工300元、管理200元、税费150元，最终调整增加50元。
- [x] 断言净经营收入8,700元、经营复盘利润1,820元、最终结算利润1,120元。
- [x] 分配先按整数商计算，再将剩余分按余数大小分配，同余数按场次编号排序；规则简单且结果可重复。
- [x] 权重缺失、负权重或非零费用对应零分母时拒绝；不自动均分。负调整先分配绝对值再恢复符号。
- [x] 分配结果保存原始费用、目标权重及尾差；测试1分钱、负1分钱和多个金额区间合计严格相等。
- [x] 与场次/SKU明细核对：SKU未分配公共项目时单列公共成本，不能声称SKU全成本利润。

核心验收示例：

```python
from src.engine.session_profit import money_to_cents, allocate_cents

def test_exact_amounts():
    assert money_to_cents("0.10") + money_to_cents("0.20") == 30
    assert money_to_cents("1.005") == 101

def test_allocation_conserves_every_cent():
    for total in range(-101, 102):
        result = allocate_cents(total, {"s1": 2, "s2": 3, "s3": 7})
        assert sum(result.values()) == total
    assert allocate_cents(1, {"s2": 1, "s1": 1}) == {"s1": 1, "s2": 0}
```
