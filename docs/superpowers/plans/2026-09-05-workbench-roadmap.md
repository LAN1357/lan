# 本地经营复盘工作台实施路线图（精简版）

**修订依据：** 用户确认减少基础设施复杂度，并明确保留精确金额、双利润和分摊金额守恒。
**目标：** 先让一名财务 BP 用两三场数据完成一次复盘，再根据真实使用情况扩展。
**设计来源：** `../specs/2026-09-04-local-live-session-close-workbench-design.md`。
**执行约束：** 遵守根目录 `AGENTS.md`，在当前会话顺序开发，不增加多智能体协作。

**M2最新确认：** 以 `2026-09-05-m2-bp-workflow.md` 为当前实施记录。固定规则命中→候选生成→人工确认；不建立评分模型。优先明确字段关联与人工确认后的复用，暂缓通用平台适配、比较分析和Agent扩展。

## 1. 不变的核算要求

- 金额使用 Decimal 处理、整数分存储和汇总，明确舍入规则。
- 同时输出经营复盘利润和最终结算利润。
- 分摊到各目标的金额合计必须等于源费用；尾差明确分配。
- 必需成本缺失必须提示并阻断关账，不能默认为零。
- 退款、优惠、佣金和平台扣费只扣一次。
- Agent 不参与核算、数据修改或关账，只解释已有的已关账结果。

## 2. 本次减重决定

| 项目 | 精简后的第一阶段 |

| 通用数据库迁移框架 | 取消；建表脚本 + 单一版本号；真正升级时增加对应脚本，升级前备份 |

首个交付允许标准模板和人工归属，不追求平台格式自动识别。M2加入固定规则候选，保留命中规则、匹配依据、异常和原始推荐；人工调整优先且不能覆盖原推荐。

## 3. 三个交付阶段

| 阶段 | 可使用的交付 | 验收重点 |
|---|---|---|
| M1 标准模板到Excel的最小闭环 | 单页本地工作台；模板导入、数据检查、人工场次归属、费用维护、双利润、月度批次关账和Excel | BP 用两三场数据完成复盘；明细可追溯；金额对得上；重开后V1保留、V2正确 |
| M2 减轻人工工作 | 固定规则候选；业务化待办与批量确认；SKU成本及投流明确关联后的复用 | 减少重复判断/筛选/录入；异常及修改依据查全；相同业务决定核算一致、历史版本不变 |
| M3 接入只读Agent | 基于已关账数据的查询、差异解释、分析摘要 | 只读工具；不访问未关账金额；数值来自后端；不自动决定合作、预算或排期 |

## 4. 必需的业务处理

### 费用完整性

按场次声明是否有达人、投流、坑位费、赠品等业务。来自源数据或BP录入的实际0元有效；可选项目可选“不适用”，留空表示尚未取得。SKU单位成本不能用“不适用”绕过；有投流却没有消耗记录、达人结算未到时不能关账。

关账页一次确认整张费用清单，不另设逐科目零确认。仓储、人工、管理费用按月维护，月度费用表统一确认完整性，不要求每场再次填写。

### 来源与更正

保留文件名、批次、业务键和来源行号。文件哈希阻止相同文件重复入账；业务键防止重叠导出重复记账。同键内容变化提示BP确认更新，不静默覆盖。

人工改归属或费用只记录对象、旧值、新值、原因和时间。保留旧行或更正前后值以供查看，不建设事件回放系统。

### 关账与历史

关账保存该版本的明细、来源引用、采用的费用及分摊方式和结果。V1不直接覆盖，重新开账后生成V2；已导出的V1报表仍能对上V1。

同一月度批次共享分摊，修改费用或分母时整批重新开账并计算，避免先开发复杂的跨批次依赖图。重开期间退出默认正式分析，旧结果可在工作台作为历史查看。

### 收入口径和时间

订单支付时间用于归属，结算状态决定是否具备最终核算条件。平台到账净额不能再扣一次已经扣除的佣金和平台费。首版标准模板直接规定金额口径，不猜测不同来源字段。

按开播业务月份组织场次复盘；源支付、结算日期另存。跨期数据在对账明细中说明，不能直接把业务月份与到账月份等同。

### 分摊与商品分析

共享费用仅分配本业务应承担的金额。BP指定受益场次及权重；缺少权重或非零费用对应零分母时阻断。系统负责算准，不替BP选一个看似合理的规则。

SKU直接贡献与公共成本分开显示；未分配到SKU的公共成本单列，满足 $\text{SKU合计}+\text{公共项目}=\text{场次合计}$。只有分配完整才称为SKU全成本利润。

### 本地数据

沿用Python和SQLite，使用独立新库 `data/workbench.db`，旧库不直接升格为已关账数据。只在需要结构升级时备份，采用SQLite备份接口；不开发通用迁移框架。

工作台仅在本机运行。Agent接入时只发送最小必要的已关账查询结果；本地存储不意味着云端模型不会收到查询结果，不发送客户个人信息或原始合同全文。

## 5. 试用与范围限制

M1 可以先用预期值明确的合成账例验证，再由BP提供脱敏数据映射到标准模板试用。没有真实平台样本验证，只能声称支持标准模板。

M1 首版Excel包含管理摘要、场次损益、核对明细、版本与口径；核对明细涵盖订单、达人、投流、成本分摊及人工修改记录。原设计中的十页分析目标在M2按实际需求扩展，不是M1出表的前置条件。

税费由BP提供已确认的损益口径金额，系统不计算应纳税额，也不将所有税款支付直接视作费用。

最终验收以“BP能完成实际复盘、数字可核对、修改能查清”为准。预测、自动决策、多用户平台、ERP API及自动PowerPoint仍不在第一阶段范围内。
